# Contributing

Contributions should preserve the template's source-free starting state and its separation between technical conformance, human admission and scientific authority.

## Change workflow

1. Read `AGENTS.md` and any narrower instructions.
2. Create a branch; do not work directly on `main`.
3. Keep each pull request limited to one reviewable purpose.
4. Update tests, documentation and `template-manifest.json` when the file set or validation contract changes.
5. Run the complete validation sequence documented in `START_HERE.md`.
6. Open a pull request and describe scope, evidence, limitations and rollback.
7. Merge only after required CI and human review.

## Knowledge changes

Knowledge candidates additionally follow `60-Knowledge-Pilot/AGENTS.md`, `ADMISSION_GATE.md` and `REVIEW_MATRIX.md`. A merge is not an admission decision. An admission decision is not scientific validation or authority to act.

Never contribute private source material, credentials, personal data, access-controlled URLs, real research results or history copied from a private research repository.

## Pull-request checklist

- [ ] Applicable agent instructions were followed.
- [ ] Sources remain external and read-only.
- [ ] Unknowns and contradictory evidence are explicit.
- [ ] No human decision, timestamp or verification was fabricated.
- [ ] Manifest and tests were updated where required.
- [ ] Validators and disclosure audit pass.
- [ ] The change does not claim scientific validity or operational authority.
